GUIDE D'INSTALLATION - NAFTAL ACCESS + DELPHI

1. PRÉREQUIS
- Windows
- Microsoft Access (ou Microsoft Access Database Engine/ACE)
- Delphi VCL avec les composants ADO (Data.Win.ADODB)

2. BASE DE DONNÉES ACCESS (AUTOMATIQUE)
Rien à faire : au premier lancement, le programme crée StockNaftal.accdb avec toutes les tables,
à côté de l'exécutable (ou dans %LOCALAPPDATA%\StockNaftal si ce dossier n'est pas modifiable).
Aux lancements suivants, il ajoute les tables ou colonnes manquantes d'une ancienne base : les
scripts 03_ et 04_ ne sont plus nécessaires. Le contenu n'est jamais effacé.
Les étapes ci-dessous ne servent que si vous voulez créer la base à la main (méthode facultative).
- Ouvrir Access > Base de données vide.
- Nommer le fichier StockNaftal.accdb.
- Placer StockNaftal.accdb dans le même dossier que l'exécutable Delphi.
- Pour chaque instruction CREATE TABLE du fichier 01_schema_access.sql :
  créer une requête en mode SQL, coller une seule instruction, puis exécuter.
- Créer les relations listées à la fin du script dans Outils de base de données > Relations.
- Pour éviter les erreurs de compatibilité, exécuter les CREATE TABLE un par un.

3. OUVRIR LE PROJET DELPHI
- Ouvrir StockNaftal.dpr dans Delphi.
- Vérifier que UnitMain.pas et UnitMain.dfm sont dans le même dossier.
- Compiler puis exécuter.
- Si la connexion échoue, vérifier que le fournisseur ACE est installé et compatible avec
  l'architecture 32/64 bits de Delphi.
- Le programme essaie lui-même ACE 12.0 puis 16.0.

4. UTILISATION
- Pour ajouter un article : saisir code, désignation et type puis cliquer Ajouter article.
- Le stock ne se modifie plus à la main : toute entrée passe par un bon de livraison, toute
  sortie par un bon d'affectation (un article est créé avec un stock de 0). Pour reprendre un
  stock existant, saisir un bon de livraison d'ouverture : créer un fournisseur de reprise
  (par exemple « STOCK INITIAL ») et y mettre les quantités et prix de l'inventaire de départ.
- Actualiser recharge la liste.
- Bon de livraison (entrée de stock) : bouton « Bon de livraison ». Choisir le fournisseur,
  ajouter les lignes (article, quantité, prix unitaire), puis Enregistrer le bon. Le stock de
  chaque article est augmenté.
- Bon d'affectation (sortie de stock) : bouton « Bon d'affectation ». Choisir le service,
  ajouter les lignes (article, quantité), puis Enregistrer le bon. Le stock est diminué ;
  l'enregistrement est refusé si le stock est insuffisant.
- Bon de commande : bouton « Bon de commande ». Choisir le service demandeur et les articles
  avec leurs quantités. Une commande n'a aucun effet sur le stock (la réception se fait par un
  bon de livraison). « Liste des commandes » permet de la consulter et de l'imprimer.
- Le numéro du bon est généré (BL-AAAA-0001, AF-AAAA-0001, BC-AAAA-0001). Un bon est enregistré en une seule
  transaction : en cas d'erreur, rien n'est enregistré.
- Fournisseurs / Services : boutons du même nom. Cliquer une ligne pour la modifier, « Nouveau »
  pour un ajout, « Supprimer » (refusé si des bons utilisent l'enregistrement).
- Consultation / impression : boutons « Liste des livraisons » et « Liste des affectations ».
  Sélectionner un bon dans la liste du haut pour voir ses lignes, puis « Imprimer le bon »
  (choix de l'imprimante ; une imprimante PDF permet d'obtenir un fichier). Un bon enregistré
  ne peut pas être modifié depuis l'application, mais il peut être annulé (voir ci-dessous).
- Correction : dans la liste, sélectionner le bon puis « Corriger le bon ». La fiche s'ouvre avec
  le contenu du bon ; modifier la date, le fournisseur/service, la commande liée ou les lignes,
  puis « Enregistrer la correction ». L'ancien bon est conservé, marqué « Annulé - Corrigé :
  remplacé par ... », et un nouveau bon (nouveau numéro) est créé. Le stock reçoit seulement la
  différence ; la correction d'une livraison est refusée si le stock deviendrait négatif. Une
  commande corrigée reprend ses livraisons rattachées.
- Annulation : dans la liste, sélectionner le bon puis « Annuler le bon » ; un motif est demandé.
  Le bon reste dans la liste, marqué « Annulé » (et imprimé avec la mention « BON ANNULÉ »).
  Livraison annulée : le stock est diminué des quantités reçues ; l'annulation est refusée si le
  stock est devenu insuffisant (articles déjà sortis). Affectation annulée : le stock est rétabli.
  Commande annulée : aucun effet sur le stock. Un bon annulé ne peut pas être « désannulé ».
- État du stock : bouton « État du stock ». Liste tous les articles avec un statut : « Sous le
  seuil » (quantité <= seuil d'alerte, en orange), « Rupture » (quantité <= 0, en rouge) ou « OK ».
  Recherche par code/désignation, case « alertes seulement », modification du seuil d'un article
  et impression. L'écran principal affiche en rouge le nombre d'articles en alerte.
- Mouvements d'un article : bouton « Mouvements article » (l'article dont le code est saisi dans
  le champ Code est présélectionné) ou « Mouvements de l'article » dans l'état du stock. Liste
  chronologique des livraisons (entrées) et affectations (sorties) avec le solde cumulé, et
  impression. Les bons annulés apparaissent en gris sans compter dans le solde. Les changements
  faits par « Entrée stock » / « Sortie stock » de l'écran principal, ou le stock de départ, n'ont
  pas de bon : ils sont regroupés sur la ligne « Stock initial / ajustements hors bons ».
- Rapprochement commande / livraison : dans un bon de livraison, le champ « Commande liée »
  (facultatif) rattache la livraison à un bon de commande. Le bouton « Rapprochement » compare,
  pour chaque commande non annulée et par article, la quantité commandée à la quantité reçue
  (somme des livraisons liées non annulées) : Non livrée / Partielle / Complète / Complète
  (excédent). Les articles reçus mais absents de la commande sont signalés « Hors commande ».
  Base existante : exécuter 04_migration_rapprochement.sql. Les livraisons déjà saisies n'ont
  pas de commande liée ; le lien ne peut pas être ajouté après coup depuis l'application.
- 02_donnees_test.sql (facultatif) : fournisseurs et services d'essai fictifs.

LIMITES DE CETTE VERSION
C'est un prototype de départ Access/Delphi. Il gère le catalogue d'articles et les quantités,
mais journal d'audit, comptes
utilisateurs et tests en environnement Windows restent à compléter. N'utilisez pas ce prototype
comme système de production sans validation et tests. Les données réelles de NAFTAL ne sont pas incluses.

5. CRÉER L'EXÉCUTABLE (.exe) À LANCER PAR DOUBLE-CLIC
- Dans Delphi : Projet > Options > Compilation, choisir la configuration « Release » et la
  plateforme « Windows 32 bits » (voir la remarque sur 32/64 bits plus bas).
- Projet > Options > Packages > Packages d'exécution : décocher « Lier avec les packages
  d'exécution », pour obtenir un seul fichier .exe autonome.
- Facultatif : Projet > Options > Application, pour choisir une icône et les informations de version.
- Projet > Construire StockNaftal. Le fichier StockNaftal.exe est créé dans le sous-dossier
  Win32\Release du dossier du projet.
- Lancement : double-clic sur StockNaftal.exe (aucune commande). Pour un raccourci sur le Bureau :
  clic droit sur le .exe > Envoyer vers > Bureau.
- Sauvegarde des données : copier le fichier StockNaftal.accdb (à faire régulièrement).

Installer sur un autre ordinateur Windows
- Copier StockNaftal.exe dans un dossier où l'utilisateur peut écrire (par exemple C:\StockNaftal ;
  éviter C:\Program Files). Le programme crée alors sa base à côté.
- Installer « Microsoft Access Database Engine » (redistribuable gratuit de Microsoft) si Microsoft
  Access/Office n'est pas installé. 32/64 bits : l'exe et le moteur ACE doivent avoir la même
  architecture. Office 32 bits ou ACE 32 bits -> compiler en Windows 32 bits ; Office 64 bits ->
  compiler en Windows 64 bits (plateforme à ajouter dans le gestionnaire de projet de Delphi).
- Windows SmartScreen peut avertir pour un programme non signé : « Informations complémentaires »
  puis « Exécuter quand même ».
